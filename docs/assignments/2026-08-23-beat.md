# Beat process — 2026-08-23 walking skeleton

Assignments are durable manager records. Seat names are functional aliases only.

## Staffing rules

1. Evidence-gathering seats return sourced findings; they do not edit production code.
2. Builders own only their assigned component in isolated branches and must commit tests with implementation.
3. The manager integrates by frozen requirements and recorded ADRs, not by majority vote.
4. Independent verification runs only after builder branches are integrated and the complete suite is green.
5. Any model-access failure is reported as `BLOCKED:<reason>` without blind retry.

## Complementary specializations

Staff complementary seats across distinct CLIs and usage pools when capacity allows. One specialization per seat. Independent review does not implement the change it reviews.

| Specialization | Duty | Isolation |
|---|---|---|
| Polling CLI builder | Machine-readable `poll-status` over the existing reader, with help text and focused tests | Isolated worktree |
| Continuity builder | Defect-driven hardening of registry, naming, resume, and status | Isolated worktree |
| Requirements verifier | CAP traceability, no-MCP/no-provider-branch checks, and test evidence | Read-only |
| Verification remediation | Resolve accepted findings with tests; preserve user-facing README contracts | Isolated worktree |

## Walking-skeleton acceptance

The bounded walking-skeleton beat is complete when an isolated checkout passes T1–T6 with two complementary locally authenticated seats:

- `grok_cli` / `grok-4.6` in usage pool `primary`
- `opencode` / `xai/grok-4.6` in usage pool `independent-review`

Required evidence: the README quickstart as installed by `uv tool install .`, durable file delivery and bounded wake, native resume after a deliberate tmux kill, registry identity before and after, and safe verified cleanup. Quality gates are a green test suite, Ruff clean, package build passing, and no MCP or provider-conditional policy findings.

The queue-starvation observation was accepted under the frozen-spec change rule as CAP-036 and ADR-0009. Full scheduling policy and a Foil-owned browser-canary suite remain future scope.
